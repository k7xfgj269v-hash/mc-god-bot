1.5.1 车万女仆 — 更新日志

错误修复

  • 已修复：女仆手持《沉浸式奏乐》乐器时右键点击，导致乐器掉落
  • 已修复：安装饰品模组（Curios）时，女仆死亡后饰品无法正确掉落（由 CentaureaHO 提供）
  • 已修复：安装配饰模组（Accessorify）后，女仆进食完毕时食物完全消失
  • 已修复：AI聊天中人格系统提示过长引发游戏崩溃

模型与渲染修复

  • 已修复：部分默认模型问题——健康值过低时“婚嫁狐妖”模型无法正常渲染

Create 模组兼容性修复

  • 已修复：破坏 Create 旋转展示台方块时额外掉落一个手办物品
  • 已修复：女仆乘坐 Create 座椅时，不随整体结构朝向同步旋转

方块与物品修复

  • 已修复：零食柜被破坏时不掉落其内部物品

模组兼容性修复

  • 已修复：NeoForge 1.21.1 下饰品栏（Curios）无法翻页
  • 已修复：与《Alex 的洞穴》共存时扫帚碰撞箱异常（由 CentaureaHO 提供）
  • 已修复：扫帚骑乘功能与《Leawind 的第三人称》存在冲突（由 CentaureaHO 提供）

AI / 网络接口修复

  • 已修复：SiliconFlow 语音识别返回 HTTP 422 错误
  • 已修复：使用新版大模型（如 GPT-4.5）配合更新后的 OpenAI API 时出现的多项兼容性问题

性能优化

  • 已优化：重构物品形态渲染逻辑，显著降低手办与座椅类物品的渲染耗时
  • 已优化：改进女仆属性值显示逻辑，防止因数值溢出导致 UI 显示异常

AI 智能体更新

本次更新对女仆 AI 聊天功能进行了全面重构，并依据主流智能体（Agent）架构设计原则进行系统性优化。目前仅已知 车万女仆：纸短情长 扩展包存在兼容性崩溃；其余所有扩展包均兼容。

支持的 AI 提供商更新

  • 更新阿里云、SiliconFlow、OpenAI 等提供商的模型列表至最新版本
  • 移除腾讯混元（Hunyuan）提供商
  • 新增以下默认提供商：
    • Gemini
    • Grok
    • OpenRouter
    • GLM
    • MiniMax（同时支持大语言模型与语音合成）
    • KiMi
    • 腾讯云（仅支持语音识别 ASR）

UI 交互改进

本次更新大幅降低了 AI 相关功能的配置门槛，显著提升了易用性。

  • 所有 AI 聊天相关设置已统一整合至面向女仆时按 T 键打开的 UI 面板中；女仆原始 GUI 中对应的功能标签页已被移除
  • 面板包含：提供商设置、女仆人格提示词编辑器、聊天记录查看与删除功能、大语言模型 / 语音合成 / 语言选项、提供商配置模块
  • 面板实时显示累计 Token 消耗量
  • 提供商配置现加入身份验证机制，全面适配单人游戏、局域网、专用服务器主机及客户端等各类场景——服务器管理员无需再担忧密钥与配置的安全性
  • 提供商配置现已支持完全在游戏内修改，无需手动编辑 JSON 配置文件
  • 聊天输入框支持使用上下方向键快速调取并重新编辑历史输入内容
  • 语音合成（TTS）提供商选择中新增“无”选项，允许玩家在客户端侧禁用语音合成

AI 聊天功能重构

  • 提示词优化

    • 女仆现可更精准识别玩家意图，并调用正确的工具
    • 每次对话均自动注入高度相关的上下文信息，以提升指令识别效率

  • 对话鲁棒性增强

    • 当大模型出现幻觉或错误调用工具时，系统将自动触发重试机制，引导模型自我修正
    • 每次对话前均校验消息历史结构，防止出现 HTTP 400 错误（此前使用 DeepSeek 等模型时常触发）
    • 若关联的女仆实体已不存在，对话会话将立即终止，避免错误调用

  • 缓存命中率优化（提升缓存命中率可有效降低 API 成本并加快模型响应速度）

    • 对话缓存命中率已从约 50% 提升至约 85%

  • 工具调用调整

    • 新增更多可调用工具，包括：切换女仆坐姿状态、开启/关闭归家模式、设置工作日程、设定攻击目标等
    • 提高工具调用链的最大轮数，并引入多重熔断机制，既支持 AI 组合多次工具调用完成复杂操作，又可防止因无限循环导致异常 Token 消耗
    • 部分富含游戏上下文的内容现通过工具调用机制按需获取，降低基础 Token 消耗
    • 使用命令 /tlm ai_chat context 可输出当前所有可用的游戏上下文信息
    • 使用命令 /tlm ai_chat tool 可输出当前所有可用的工具列表

  • 技能系统

    • 新增技能（Skill）系统：标准技能文件可放置于配置文件夹或数据包指定路径下，系统将在适当时机将其注入对话上下文
    • 内置一个默认技能，包含关于女仆模组本身的全部知识，使女仆能够准确回答有关该模组的问题
    • 使用命令 /tlm ai_chat skill 可输出当前已加载的所有技能

  • 上下文压缩

    • 当对话历史达到一定长度时，系统将自动压缩并总结历史记录，在保持对话连贯性的同时有效降低 Token 消耗

  • UI 反馈改进

    • 女仆执行工具调用时，聊天气泡将实时刷新以显示当前工具调用状态，减少等待期间玩家困惑
    • 调整常规文本聊天气泡最大宽度，防止单行过长影响可读性

新增内容

新模型

  • 更新：K 蜗牛模型
  • 新增：圣洁狐妖、精灵狐妖（Starfield）、幸存者狐妖（Rosemist）、迷你狐妖（White Polarbear）、战术狐妖（Sodaball Pixel）
  • 新增：年糕狐（完美冻结）
  • 新增：《东方禁书目录》中缺失角色（FumoFumo）
  • 更新：灵梦与魔理沙模型（CrystalSun）

精妙背包支持

新增对《精妙背包》模组的兼容支持：将精妙背包放入女仆的饰品栏（Curios slot）后，女仆即可正常与其交互，包括取出和放入物品。（由 CentaureaHO 提供）

迷你女仆妖精

当女仆妖精生成时，现存在 10% 概率生成迷你女仆妖精。迷你女仆妖精飞行速度略高于普通女仆妖精，被击杀后掉落双倍 P-点数。

回退原料（FallbackIngredient）

新增 FallbackIngredient 类型配方原料，用于在多模组环境中实现差异化合成输入（设计理念类似于 Avaritia 合成台的多模组适配方案）。

该原料类型按顺序遍历 fallbacks 列表，选取首个已安装对应模组的条目作为实际合成输入，实现“若模组 A 存在则使用其物品，否则回退至模组 B”的逻辑。

使用示例：

以下配方演示了一个祭坛配方：若安装了《森罗物语：厨房》，则使用其石磨；否则回退至原版木板（标签匹配），且始终要求一颗钻石作为固定原料：

{
  "type": "touhou_little_maid:altar_recipe",
  "output": {
    "item": "touhou_little_maid:bookshelf",
    "count": 1
  },
  "power": 0.1,
  "ingredients": [
    {
      // 必填类型参数
      "type": "touhou_little_maid:fallback_ingredient",
      // 有序列表；首个已安装模组的条目将被选为实际输入
      "fallbacks": [
        {
          // 若安装了 kaleidoscope_cookery，则使用其石磨
          "modid": "kaleidoscope_cookery",
          "value": {
            "item": "kaleidoscope_cookery:millstone"
          }
        },
        {
          // 回退方案：使用原版木板（标签匹配）
          "modid": "minecraft",
          "value": {
            "tag": "minecraft:planks"
          }
        }
      ]
    },
    // 固定原料：钻石（原版 Ingredient 语法）
    {
      "tag": "forge:gems/diamond"
    }
  ]
}

备用原料（FallbackIngredient）

新增 FallbackIngredient 类型的合成原料，用于在多模组环境中实现差异化合成输入（设计理念类似于Avaritia合成台的多模组适配方案）。

该原料类型按顺序遍历 fallbacks 列表，选取首个对应模组已安装的条目作为实际合成输入，实现“若安装模组A则使用其物品，否则回退至B”等逻辑。

使用示例：

以下配方演示了一个祭坛合成配方：若安装了《森罗物语：厨房》，则使用其磨石；否则回退至原版木板；同时始终要求一颗钻石作为固定原料：

{
  "type": "touhou_little_maid:altar_recipe",
  "output": {
    "item": "touhou_little_maid:bookshelf",
    "count": 1
  },
  "power": 0.1,
  "ingredients": [
    {
      // 必填类型参数
      "type": "touhou_little_maid:fallback_ingredient",
      // 有序列表；选取首个已安装模组对应的条目作为实际输入
      "fallbacks": [
        {
          // 若存在则使用《森罗物语：厨房》的磨石
          "modid": "kaleidoscope_cookery",
          "value": {
            "item": "kaleidoscope_cookery:millstone"
          }
        },
        {
          // 回退：使用原版木板（标签匹配）
          "modid": "minecraft",
          "value": {
            "tag": "minecraft:planks"
          }
        }
      ]
    },
    // 固定原料：钻石（原版Ingredient语法）
    {
      "tag": "forge:gems/diamond"
    }
  ]
}

    • 女仆可使用《卓越前线》中的枪械（毒刺导弹除外）
    • 当女仆弹药耗尽时，将尝试使用副手持有的 RGO 手榴弹（要求主手持有枪械，副手持有 RGO 手榴弹）
    • 拾起佩戴鞍具的女仆后，对载具右键即可让女仆直接坐入驾驶员座位
    • 玩家乘坐载具时，附近跟随的女仆可坐入乘客座位
    • 坐在驾驶员或乘客座位上的女仆可使用载具武器或手持武器进行攻击
    • 放置在背部装饰栏位的武器将在女仆背部或腰部显示

  • 优化远程攻击 AI 机制

    • 在远程模式下，女仆将优先攻击当前正在伤害自身的生物

  • doMobLoot 规则现影响女仆妖精的能量点掉落

  • 移除 actuallyHurt 方法，修复女仆在 Arclight 服务器上受伤即死的 Bug

  • 新增对小地图模组的兼容性支持

    • 兼容 Xaero 的小地图模组实体图标，现女仆、妖精女仆、扫帚、坐垫及能量点均已拥有专属实体雷达图标
    • 兼容旅行地图模组，当女仆死亡时，死亡坐标将显示于聊天栏，便于在旅行地图中快速添加路标

  • 新增女仆备份机制，可在异常情况下自动备份女仆数据，并快速恢复此前备份的女仆

    • 首先需在 touhou_little_maid-server.toml 文件中启用女仆自动备份功能（默认关闭）

      # 是否启用女仆备份机制，该机制将定期备份服务器上所有玩家的女仆数据
MaidBackupEnable = false
# 女仆备份机制中备份女仆数据的时间间隔（单位：秒）
# 取值范围：> 5
MaidBackupIntervalSeconds = 180
# 启用女仆备份机制后，每位玩家最多保存的备份数量
# 取值范围：1 ~ 64
MaidBackupMaxCount = 3

    • 游戏随后将根据设置，在已加载的区块内定期备份女仆

      • 备份采用异步机制，避免阻塞主服务器线程导致卡顿
      • 备份时间随机分布，防止集中在同一游戏刻造成卡顿

    • 使用 /tlm backup get <玩家> 命令可查看该玩家全部备份数据，点击显示条目可进一步查询

    • 最终向命令执行者发放一张包含备份数据的女仆照片

  • 修改近战伤害逻辑，新增事件

    • 现调用 net.minecraft.world.item.Item#hurtEnemy 方法，在近战攻击后触发相关逻辑（如耐久消耗）
    • 新增 MaidHurtTarget.Pre 与 MaidHurtTarget.Post 事件，用于在近战攻击过程中触发

  • 更新部分模型

    • 三款琪露诺女仆模型与两款雕像坐垫模型
